# IluminOS

Учебная 64-битная операционная система, написанная с нуля на Rust и работающая на голом железе (в QEMU). От загрузки до графического интерфейса с браузером — всё своё, без стандартной библиотеки.

Около 4000 строк собственного кода в 17 модулях.

![Терминал IluminOS](https://raw.githubusercontent.com/IbrokhimN/IluminOS/refs/heads/main/docs/tty.png)

## Что умеет IluminOS

- грузится через загрузчик Limine в 64-битном режиме
- собственный графический вывод (шрифт, цвет, курсор, скроллинг, баннер)
- драйверы клавиатуры, мыши и диска, написанные вручную
- файловая система с динамическим выделением блоков, inode и папками
- командная оболочка (shell) с набором команд
- текстовый редактор в стиле vim с подсветкой синтаксиса
- динамическая память (своя куча и аллокатор)
- аппаратный генератор случайных чисел
- исполнение WebAssembly-модулей (через встроенный wasmi)
- собственный интерпретируемый язык программирования
- графическая оболочка в стиле Windows 3.1 с мышью
- браузер Not-Google с парсером и рендерингом HTML
- набор приложений: терминал, часы, калькулятор, Paint

## Быстрый старт

Требования: Rust nightly с таргетом `x86_64-unknown-none`, QEMU, Limine.

Сборка и запуск:

```bash
make run QEMUFLAGS="-m 2G -device piix3-ide,id=ide -drive id=disk,file=fs.img,format=raw,if=none -device ide-hd,drive=disk,bus=ide.0"
```

Или через скрипт:

```bash
./run.fish
```

## Архитектура

Проект собран из 17 модулей, каждый отвечает за свою подсистему.

### Загрузка и вывод

**main.rs** — точка входа `kmain`. Объявляет запросы к Limine (фреймбуфер), инициализирует подсистемы по порядку: аллокатор, генератор случайных чисел, файловую систему, затем запускает оболочку.

**framebuffer.rs** — весь вывод на экран. Limine даёт графический фреймбуфер (массив пикселей), готовых букв нет — каждый символ рисуется пиксель за пикселем по таблице шрифта `font8x8`. Поддержка цвета, курсора, скроллинга, а также графических примитивов для GUI (прямоугольники, рамки, текст в произвольной позиции, масштабируемый текст).

**banner.rs** — стартовый ASCII-баннер IluminOS с цветовым градиентом.

### Драйверы

**port.rs** — чтение и запись портов ввода-вывода через ассемблерные вставки (`inb`/`outb`). Написано вручную вместо внешнего крейта, чтобы убрать зависимость, несовместимую с современным компилятором.

**keyboard.rs** — драйвер PS/2 клавиатуры опросом (polling). Читает скан-коды, переводит в символы, обрабатывает Shift и Caps. Различает байты клавиатуры и мыши по биту статуса.

**mouse.rs** — драйвер PS/2 мыши. Инициализирует второй канал контроллера, читает пакеты по 3 байта (кнопки и смещения), двигает курсор.

**ata.rs** — драйвер диска (ATA PIO). Читает и пишет секторы через порты с таймаутами. Работает с контроллером piix3-ide.

### Хранение данных

**fs.rs** — файловая система. Динамическое выделение блоков через битовую карту, inode с переменным размером файла, иерархия папок через указатель на родителя. Есть текущая рабочая директория и построение путей.

**allocator.rs** — куча и глобальный аллокатор. Даёт динамическую память (`Vec`, `String`, `Box`) через `linked_list_allocator` поверх статической области.

**random.rs** — генератор случайных чисел на основе счётчика тактов процессора (`rdtsc`) как источника энтропии и `xorshift64` как PRNG.

### Оболочка и редактор

**shell.rs** — командная оболочка (REPL). Читает команду, выполняет, печатает результат. Приглашение показывает текущий путь.

**editor.rs** — текстовый редактор в стиле vim. Три режима (обычный, вставка, команда), навигация hjkl, подсветка синтаксиса Rust.

### Исполнение программ

**wasm.rs** — исполнение WebAssembly через встроенный интерпретатор `wasmi`. Вкомпилированный модуль с функциями `add`, `factorial`, `fib` исполняется внутри ОС на голом железе.

**script.rs** — интерпретатор собственного мини-языка. Токенизатор и парсер методом рекурсивного спуска с правильным приоритетом операций. Поддерживает переменные (`let`), вывод (`print`), арифметику со скобками.

### Графический интерфейс

**gui.rs** — графическая оболочка в стиле Windows 3.1. Рабочий стол с иконками, окна с заголовками и объёмными гранями, кнопки закрытия, маршрутизация событий мыши. Содержит терминал и браузер Not-Google.

**html.rs** — парсер подмножества HTML. Поддерживает заголовки h1-h6, абзацы, форматирование (b, i, u, code), цвет (font color), списки (ul, ol, li), ссылки, цитаты, разделители. Выдаёт список блоков для рендеринга.

**apps.rs** — приложения GUI: часы (время работы через счётчик тактов), калькулятор (машина состояний, управление мышью), Paint (растровый редактор с палитрой и рисованием мышью).

## Ключевые технические решения

### Почему Limine, а не свой загрузчик

Написание загрузчика с нуля — отдельный большой проект (переключение режимов процессора, настройка страниц памяти, разбор ELF). Изначально проект использовал `bootloader 0.9`, но тот оказался несовместим с современным компилятором из-за цепочки зависимостей. После нескольких неудачных сборок был выполнен переход на Limine, который зависит только от `core` и тонкого крейта `limine`. Урок о хрупкости bare-metal экосистемы на нестабильном компиляторе.

### Почему вывод английский

Шрифт `font8x8` в наборе BASIC_LEGACY содержит только ASCII. Кириллица в UTF-8 занимает два байта на символ и не отрисовалась бы корректно.

### Почему опрос, а не прерывания

Клавиатура и мышь читаются опросом (polling), а не через прерывания. Опрос проще (не нужны таблица прерываний, обработчики, очереди), хотя процессор при этом тратит такты вхолостую. Для однозадачной системы это приемлемо. Прерывания — направление дальнейшего развития.

### Почему WebAssembly вкомпилирован, а не читается с диска

Файлы в ФС ограничены размером, и нет способа загрузить бинарный модуль в ОС извне. Поэтому демонстрационный wasm-модуль встроен в ядро через `include_bytes`.

### Почему двойная буферизация не используется

Полная двойная буферизация требует копировать весь экран каждый кадр. На голом железе без графического ускорения это копирование выполняется процессором и слишком медленно (заметное падение частоты кадров). Поэтому применяется частичная перерисовка — обновляется только изменившаяся область (например, участок под курсором мыши).

### Почему нет реальной сети и WiFi

Настоящая сеть требует драйвер сетевой карты, TCP/IP-стек, а для интернета — DNS и TLS. Это отдельная большая работа. Браузер Not-Google работает на локальных данных: рендерит HTML-файлы из файловой системы и имитирует поисковую выдачу по шаблонам.

## Как работают ключевые подсистемы

### Файловая система

Диск разбит на области: суперблок, битовая карта свободных блоков, таблица inode, блоки данных. Каждый файл описывается inode, который хранит массив номеров блоков с данными (а не фиксированный адрес), что даёт переменный размер файла. Папка — это тоже inode с флагом директории; принадлежность файла к папке задаётся указателем на родительский inode. Так строится дерево каталогов.

### Динамическая память

Типы `Vec`, `String`, `Box` лежат в крейте `alloc`. Чтобы они заработали в `no_std`, объявлен глобальный аллокатор (`linked_list_allocator`) поверх статической области кучи. Аллокатор хранит список свободных блоков, выдаёт по запросу и сливает соседние при освобождении. Освобождение автоматическое через механизм Drop.

### Интерпретатор своего языка

Работает как настоящий интерпретатор: токенизатор разбивает текст на токены, парсер методом рекурсивного спуска строит вычисление. Приоритет операций возникает автоматически из вложенности функций разбора: сложение вызывает умножение для своих операндов, поэтому умножение "связывает крепче". Переменные хранятся в таблице.

### Рендеринг HTML

Парсер идёт по тексту, находит теги, между ними — текст. Ведётся текущий стиль (размер, цвет, начертание): открывающий тег меняет стиль, закрывающий возвращает. Текст между тегами наследует активный стиль. Парсер выдаёт список блоков, рендерер рисует каждый своим шрифтом, цветом и отступом. Заголовки крупнее за счёт масштабирования: каждый пиксель глифа рисуется квадратом NxN.

### Генерация случайных чисел

На голом железе нет ОС-источника случайности. Энтропия берётся из счётчика тактов процессора (`rdtsc`), младшие биты которого зависят от точного тайминга. Из этого получается seed, а поток чисел порождает быстрый PRNG `xorshift64`.

## Демонстрационный сценарий

Последовательность для показа всех возможностей:

```
help                    все команды
about                   об авторе
mkdir projects
cd projects
pwd                     показывает /projects
edit hello.rs           редактор с подсветкой, написать код, Esc
cat hello.rs
cd /
df                      использование диска
mem                     куча
memtest                 динамическая память в действии
rand 100                случайное число
wasm                    исполнение WebAssembly (42, 120, 55)
edit prog.txt           написать: let x = 5 / print x * 10
run prog.txt            исполнить свой язык
edit page.html          написать HTML: <h1>Hello</h1><p>text</p>
gui                     графический режим
```

В графическом режиме:

- клик по иконке Terminal — терминал в окне
- клик по Not-Google — браузер, ввести `page.html` и Search для рендера
- клик по Clock — часы
- клик по Calc — калькулятор (кликать кнопки мышью)
- клик по Paint — рисование мышью с палитрой
- клик по `[x]` — закрыть окно
- Esc — выход в консоль
